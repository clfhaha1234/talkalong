# Design / ADR — Typed-Segment Proactive-Agenda Engine

> **Status:** Accepted (architecture exploration). Demos/tests only — no product deadline.
> **Date:** 2026-05-29
> **How we got here:** brainstorming + grill-me over the architecture, grounded in three run experiments:
> [agentic-vs-singleshot](../experiments/2026-05-29-agentic-vs-singleshot/conclusion.md),
> [interrupt-smoothness](../experiments/2026-05-29-interrupt-smoothness/conclusion.md),
> [climax-leak](../experiments/2026-05-29-climax-leak/conclusion.md).

## Problem

We want a **general** engine for *proactive, interruptible, agenda-driven* voice agents — one that
(1) drives its own agenda, (2) lets the user barge in anytime, (3) returns to the main line without
losing place, and (4) dynamically adjusts **delivery** (style/pace/language) but **not** the content's
integrity. Storytelling is only the first demo; the real question is **does the engine generalize?**

## Decision 1 — Architecture: two LLM roles + a deterministic spine (NOT an agentic agent)

| Role | What | Owns | When it runs |
|---|---|---|---|
| **Fast voice agent** (Agora-hosted, gpt-4o-mini) | a real real-time agent | live QA answers, voice I/O, turn-taking | every turn, low-latency |
| **Deliberation brain** (Gemini, **single-shot** structured call) | NOT an autonomous agent — one decision call | boundary decisions: resume strategy, answer-adequacy, turn classification, policy directives | only at boundaries |
| **Spine** (`ProgressState`, plain code) | NOT an agent — a deterministic state machine | **the single source of truth** (progress/agenda), *when* to invoke the brain, enforcing invariants, applying policy flags | always |

**Pattern: proposer / disposer.** The LLM roles *propose*; the spine *disposes* (validates against
invariants, applies, or rejects). The two LLM roles never negotiate with each other — the spine
mediates. Control flow belongs to the spine, never to a model.

**Why not a more agentic (tool-using, flow-owning) agent?** Measured, not asserted:
[agentic-vs-singleshot](../experiments/2026-05-29-agentic-vs-singleshot/conclusion.md) compared a real
function-calling tool-loop planner vs the single-shot planner on the interrupt benchmark — **equal
decision quality (9.67 vs 10.0/11), 3.65× latency, ~5× tokens.** On a bounded decision where all inputs
are known up front, agentic round-trips are pure overhead. Revisit only if a future task needs the agent
to take **real external actions mid-decision** that one prompt cannot pre-load.

## Decision 2 — The unifying abstraction: typed segments

An **agenda is a sequence of segments**, each typed by its **completion semantics**:

- **`deliver`** — the agent narrates authored content. *Complete when* the audio is spoken.
- **`elicit`** — the agent asks and waits for the user. *Complete when* the answer is **adequate**
  (quality) **OR** a non-response timeout / give-up cap fires (timing).

One spine, segment polymorphism. The three target scenarios are just different mixes — **change the
agenda data, not the engine:**

| Scenario | Content ownership | Agenda |
|---|---|---|
| Storytelling (have) | AI-output-dominant | all `deliver` |
| HR interview | user-input-dominant | all `elicit` |
| Enterprise onboarding | bidirectional | `deliver` + `elicit` interleaved — the composition proof |

## Decision 3 — Elicitation: proactive ask + non-response handling

The `elicit` segment carries an authored **target/rubric** (1–2 lines: "a satisfactory answer surfaces X").
Each turn, the single-shot brain reads `{question, target, user answer | silence, attempts-so-far}` →
`{accept-and-advance | follow-up(text) | give-up-and-advance(bridge)}`.

- **Timeout** uses Agora's native `silence_config {timeout_ms, action}` — no bespoke timer.
- **Give-up** has a cap (≤K follow-ups / ≤T seconds) → a warm transition ("that's alright, let's move
  on") then advance. This is the *teacher continues the lesson* behaviour.
- **Targets are authored cheaply:** generated by a second LLM pass **during the image-generation latency
  window** after the script/outline is produced — zero added user-facing latency, and keeps targets
  same-sourced with the agenda.

## Decision 4 — First-principles request classification (not an edge-case list)

Every user utterance is classified by **which layer it touches** — this is the durable rule; enumerating
edge cases is futile.

| Class | Touches | Action |
|---|---|---|
| **QA** | wants information | answer (bounded by the spoiler invariant), then resume |
| **HOW / delivery** | language, style, persona, pace, verbosity, "stop asking" | **accept** → durable spine **policy flag** |
| **WHAT / integrity** | plot, canon, reveal-order, abandoning the task | **gracefully refuse / deflect**; spine invariants hold the line |

One line: *changes only HOW it's told → accept; changes WHAT is told / the reveal order / the task itself
→ refuse.* (Li Bai style, Japanese = HOW ✓. Spoil the ending, switch to telling jokes = WHAT ✗.)
**Compressible, not droppable:** pace/detail are adjustable, but the spine's **coverage invariant**
guarantees load-bearing segments still get hit (compressed, never dropped). "Spoil the ending" is the
**no-early-reveal invariant already shipped** in the climax-leak experiment.

**Policy flags are spine state, not LLM memory** — a directive flips a durable flag
(`elicitation_enabled`, `language`, `style`, `pace`) that survives N turns; we do **not** rely on the
conversational LLM "remembering" it (that's the agentic-drift failure mode).

## Validation — how we prove generality with data

Ground truth for user-input-dominant scenarios comes from **simulated interviewees**: independent LLM
personas (no shared state with the agent under test) driving the user side, each stressing one behaviour:

| Persona | Tests |
|---|---|
| cooperative | adequacy judged correctly; coverage |
| rambling / off-topic | pulled back; agenda not derailed |
| shallow answerer | partial → one follow-up |
| won't-answer / shy | silence timeout → graceful skip |
| meta-instruction ("stop asking" / "in Japanese") | 3-way classification → spine flag |

Grade against the agenda's targets: `{load-bearing coverage % (deterministic gate) | adequacy-judgment
accuracy (LLM judge) | graceful non-response | zero WHAT-violations}`. Reuses the existing `run.ts` /
`grade.ts` harness shape — personas are the fixture, behaviours are the case dimensions.

## Scope — the minimal falsifiable experiment (NOT three products)

1. Upgrade the spine to **typed-segment** (`deliver` / `elicit` completion semantics).
2. Author **three tiny agendas**: deliver-only (reuse the story), elicit-only (3–4 HR questions + targets),
   mixed (onboard: 2 deliver + 2 elicit).
3. Run **one engine** over all three + simulated interviewees. **Change data only, not code → generality
   proven. Whichever agenda forces a spine change → that's the hidden storytelling-coupling to fix.**

Onboarding is the prize (composition proof), built as a tiny mixed agenda, **not** a product.

## Deferred to data (tuning, not architecture)

- Non-response timeout / follow-up cap values (K, T) — calibrate against simulated interviewees.
- "Stop asking" reversibility + scope (this question vs whole session) — a flag-semantics detail.

## Consequences / non-goals

- We are **not** going agentic (data-killed). We are **not** building three products. We are **not**
  chasing more storytelling-benchmark quality (noise floor).
- Net: the engine's "brain" stays a single-shot decision; the "intelligence" lives in (a) better
  authored agendas + targets and (b) the spine's invariants — both testable.
